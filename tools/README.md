# 任意角度水印解析检查

仅使用 R/B 多方向频谱模板，不需要未旋转的截图。W2 的 G 通道正文、头部、交织、纠错和密钥协议保持不变。
解析入口为：读取图片 → 默认位置直接读取 → 原尺度头部预检。头部证据强时先验证原尺度裁剪位置，成功即可省去 FFT；否则只进行一次多方向频谱预检，再根据角度、尺度与镜像证据安排原尺度、缩放、旋转三条路径的优先顺序。优先路径未认证时，在预算内尝试其余路径；最后尝试屏幕尺寸补偿。旋转路径先验证 90°、180°、270° 及各自镜像，再处理频谱角度候选。
角度估计保留至多四个几何候选，每个候选检查 180° 歧义及镜像，最终仍须通过本机 GCM 认证。

## 多方向模板设计

- R 通道波矢：`(16,0)`、`(21,0)`、`(9,12)`、`(12,16)`；B 通道：`(0,16)`、`(0,21)`、`(-12,9)`、`(-16,12)`，均以 672 像素为周期。对应四个方向为 0°、90°、约 53.13°、143.13°。
- 每个分量振幅为 30。每通道定位信号 RMS 从旧版 60 降到约 42.43，总交流能量约为旧版一半；原有横纵分量的振幅减半，额外能量分散到斜向。所有分量叠加的绝对值上界为 120，中心值为 128，无需裁切波形。
- 斜向分量使用固定不同相位，横纵分量使用零相位供投影和位置估计。整数波矢确保平铺边界连续。
- 模板的所有频谱候选都使用八个已知峰联合评分，并显式考虑镜像造成的方向关系变化。横纵和斜向频率组均可提供候选初值，不再提供独立的四峰模板匹配分支。日志 `angle_candidate` 使用 `template=multi`。
- 本次主要比较可见条纹、解析率和耗时；分散频谱和降低能量不保证所有背景下不可见。显示与截图正文的强度保留。此前系统编辑器自动放大裁剪的问题仍需单独实测和分析。

## Android Studio 实测

1. 更新应用后关闭并重新开启水印，再生成新截图，确保悬浮层已使用多方向模板。
2. 分别测试 0°、90° 和任意角度（如 7°、29.3°、45°、137.4°），再测试裁剪、缩放和镜像。
3. Logcat 筛选 `tag:SystemWP`；进一步用 `timing` 查看各阶段耗时，使用 `locator run=编号` 关联一次解析。
4. 对比 `angle_candidate`（角度/比例初值）、`angle_result`（头部精化结果和认证状态）、`orientation complete`（本次定位总耗时）。界面显示的是顺时针补偿角度，而非编辑器中施加的旋转角度。

解析期间同时显示八个彩色步骤，不显示横向进度条：读取、默认位置读取、原尺度头部预检、频谱预检、原尺度路径、缩放路径、旋转镜像路径、屏幕补偿。使用灰色“待执行”、蓝色“进行中”、绿色“已完成”、橙色“已跳过”，支持深色模式。步骤执行顺序可以因分流改变，界面按实际执行记录状态，不按列表位置推断完成；完成表示该路径已结束尝试，不代表认证成功。标题显示已处理步骤数。成功、失败或取消后隐藏实时步骤，保留结果及耗时，并单独显示“步骤执行记录（按结束顺序）”。跳过的步骤不计入完成记录；取消时正在执行的步骤不计入。录屏实时列表换帧重置，结束后的完成记录保留各帧的步骤与帧序号。开始新任务时清空上一次记录。

## 分流与预算

- 原尺度预检：最多 36 个像素相位、每相位 64 个已知头部槽位进行相关搜索，保留最多四个位置。预检预算 1500 ms，其中粗位置搜索约 900 ms；已完成相位的位置候选缓存在本次图片任务内供原尺度路径复用。
- 头部强证据：头部相关分数至少 0.3，已知 16 位至少匹配 14 位，覆盖至少 128 个头部副本槽位，同向性至少 0.25。只用于选择尝试顺序，最终仍要求 GCM 认证。
- 频谱候选幅度至少 0.04 时参与优先级判断：补偿角离 0° 不超过 0.35° 且无镜像时，按比例是否偏离 1 超过 0.01 选择原尺度或缩放优先；有旋转或镜像时旋转路径优先。证据弱时原尺度优先，不据此硬排除其他路径。
- 原尺度路径预算 10000 ms，只按 0°、比例 1 搜索裁剪位置，最多验证四个位置；不重复已完成的预检相关计算。
- 无旋转缩放路径预算 50000 ms，共用本任务频谱结果，横纵投影与尺度定位结果按图像方向缓存。最多三个尺度初值，每个初值检查中心及相邻恢复宽度对应的尺度，并限时搜索裁剪位置；不进行任意角度枚举。
- 旋转与镜像路径预算 200000 ms，先依次验证 90°、180°、270°，每个角度检查非镜像和镜像。固定方向先直接读取，再限时检查最多三个尺度及裁剪位置。均未认证后，继续最多四个频谱几何候选及各自 180° 歧义和镜像组合；使用相位定位、头部精化及限时位置搜索。没有频谱角度候选时仍尝试固定角度。
- 频谱连续精化共用 2500 ms 的软预算；到期保留当前估计，不丢弃所有候选。FFT 准备及基本候选评分另计，因此这些预算不构成整个任务的严格总时限。搜索预算按单调时钟的墙钟时间控制，设备越慢，实际覆盖的位置和候选可能越少。
- 每条路径至多尝试一次，任意路径认证成功即返回。路径预算耗尽时，实时列表以红色显示“达到路径预算，已退出”，后续切换路径也不会将其改为“已完成”；结束后的步骤执行记录保留该原因。用户取消会直接中止任务，不会被当作路径预算耗尽而继续回退。日志 `routing` 显示顺序，`route start/complete` 显示预算及结果。

建议对比原始完整截图、无旋转局部裁剪、局部裁剪后等比放大、任意旋转放大裁剪、90° 加镜像五组样本，分别记录命中的路径和耗时。前两类成功时重点检查是否省去了 FFT。

解析结果界面显示头部预检、原尺度路径、缩放路径、旋转路径、角度估计、角度头部精校准、角度正文解码及定位总耗时，单位为毫秒。同名阶段按候选累计，录屏按已解析帧累计。未执行的阶段标为“未执行”。路径总计与子阶段不能相加；定位总耗时不含之后的屏幕尺寸补偿。

| stage | 含义 |
| --- | --- |
| `header_probe` | 原尺度头部预检 |
| `route_original` | 原尺度位置搜索及认证 |
| `route_scaled` | 无旋转缩放和位置搜索及认证 |
| `route_rotation` | 旋转及镜像路径总计 |
| `angle_prepare` | 色差图和块平均 |
| `angle_fft` | 加窗及两通道二维 FFT |

| `angle_spectral_refinement` | 连续频率上的角度/比例精化 |
| `angle_estimation` | 以上角度估计阶段的总计 |
| `angle_projection` | 候选方向的色差投影 |
| `angle_scale_position` | 模板横纵分量的尺度、相位与位置搜索 |
| `angle_header_position` | 已知头部的位置、尺度精化 |
| `angle_header_refinement` | 用头部进一步精化角度、位置和尺度 |

耗时为单调时钟的墙钟毫秒数。总计包含子阶段，不能将总计与子阶段相加。定位总耗时不含之前的文件解码和默认位置读取。候选路径在各自预算内回退结束后进入屏幕尺寸补偿。

当前尺度补偿范围沿用 `0.45..1.10`。算法跳过映射到图片范围外的采样点；图片文件内已有的黑白填充边框仍属于观测内容，此版本不自动分割填充区域。严重压缩、裁剪或正文信号损坏仍可能导致认证失败。

## 不依赖设备的角度检查

在 PowerShell 中运行 `./tools/check-watermark-angle.ps1`，使用 Android Studio JBR 和本机已缓存的 Kotlin 2.2.10 编译器，不下载依赖；路径不同时可传 `-JavaHome` 和 `-GradleCacheRoot`。

检查覆盖多方向模板、多角度、缩放、镜像、非方形裁剪窗口、模板平铺/幅度边界、纯色图和取消操作。它验证角度/尺度估计，不替代实际截图、Android Keystore 或整应用构建验证。

结束结果独立显示“频谱预检角度（顺时针补偿候选）”，保留三位小数，数据直接来自频谱预检完成事件，而非固定角度枚举或头部精校准。仅对实际进入旋转与镜像路径的图片或视频帧保留该项；成功、失败、预算退出或取消均适用。频谱预检完成但没有候选时显示“未得到可用角度候选”；未进入旋转路径则不显示此项。

## 八信号联合精定位回退

固定 90°/180°/270° 及现有频谱候选解析均未认证后，如果旋转路径仍有超过 2000 ms 的预算且存在频谱候选，再进入八信号联合精定位。已有成功结果直接返回；生成模板、原尺度/缩放路径及各自预算保持原值。

- 直接从收到的截图读取 `R−G`、`B−G`，在源图片坐标中使用单个中央窗口做块平均、加窗。步长至多 6、窗口至多 192×192 个样本，不预先旋转图片，不使用横纵投影，也不需要原始截图或原始尺寸。
- 复用最多四个频谱角度和尺度初值，检查各自 180° 歧义和镜像。每通道同时回归四个定位波的正弦、余弦系数及一个背景平面，提取幅度和相位。
- 根据非共线信号的相位生成周期位置候选，以全部八个波的加权相位一致性消除周期歧义。平移表示源图片中心对应的水印坐标。
- 最多保留四个几何候选，再用带阻尼的联合拟合更新角度、尺度、平移及背景、通道幅度。模型考虑块平均的频率衰减，并限制局部彩色背景的影响。此处是定位信号拟合，没有新增更大范围的头部角度搜索或多区域检测。
- 转换为现有采样器的偏移：`offsetX = centerX - scale × 旋转视图宽度 / 2`，Y 同理，按 672 周期归一化。随后继续现有头部校准、正文纠错和 GCM 认证；信号拟合分数本身不作为身份认证。
- 联合拟合使用最多 30000 ms 的软预算，并从旋转路径剩余预算中预留约 1500 ms 用于候选解码；总旋转路径仍受 200 秒预算控制。软预算到期保留已得到的候选；用户取消和总路径预算退出沿用现有处理。

界面新增 `八信号联合精定位准备`、`八信号联合拟合`、`联合精定位候选解码` 三项耗时；没有进入此回退时显示“未执行”。Logcat 使用 `joint_phase`、`joint_geometry`、`joint_decode` 查看相位一致性、拟合后的几何和认证结果。结果中的“频谱预检角度”仍显示原始预检候选；成功后的旋转补偿显示实际认证采用的角度。

Android Studio 建议重点验证：任意旋转后裁剪至 969×1551 的图片，以及叠加等比放大和镜像的样本；对比是否进入联合回退、是否通过认证及上述耗时。同时复测原始完整截图、无旋转局部截图、缩放局部截图和 90° 镜像截图。此回退仍依赖可用频谱初值，严重信号损坏不能保证恢复。
